# Hard Hat Mack — C 변환판 + VGA 256색 리마스터

1984년 Electronic Arts 의 *Hard Hat Mack* IBM PC 판(`HHMACK.COM`, Dana How & Kevin Gilmore)을
역어셈블해 C 로 옮기고, 게임 규칙·빠르기·소리는 원본 그대로 둔 채 화면만 VGA 256색으로 다시 그린 것이다.

| | |
|---|---|
| `HHMACK.EXE` | 원본과 똑같이 동작하는 판 (CGA 4색) |
| `HHVGA.EXE` | 같은 게임, 화면만 VGA 256색 |

바로 돌려볼 수 있는 실행 파일은 [`release/`](release) 에 있다 (`CWSDPMI.EXE` 와 한 폴더에).

## 어떻게 옮겼나

원본은 애플 II 6502 판을 기계적으로 8086 으로 옮긴 손 어셈블리다.
애플식 7화소 칸, 줄 표(`052D`)로 더해지는 20화소 여백, 타이머 없이 CPU 빠르기로 재는 시간 같은
버릇이 그대로 남아 있다.

* `tools/asm2c.py` — 프로그램 전체를 **함수 하나**(`hh_run`)로 옮긴다.
  `call` 은 돌아갈 자리를 흉내 낸 메모리 `M[]` 에 쌓고, `ret` 은 돌아갈 자리로 가는 `switch` 가 된다
  (쌓기 순서까지 원본과 같다).  깃발(flag)은 쓰이는 곳을 따져 필요할 때만 셈한다.
* 8088 클럭 수를 세어 `cyc` 에 모으고, `sys_dos.c` 가 이를 PIT(= CPU/4)에 맞춰 늦춘다.
  그래서 4.77MHz IBM PC 의 빠르기와 스피커 음높이가 그대로 나온다.
* 키는 원본이 키를 보던 자리([0781])에서만 넣는다.

## VGA 리마스터

CGA 화면 메모리에 글을 쓸 때마다 **어느 그림의 몇 번째 바이트에서 왔는지**를 화소마다 적어 둔다(꼬리표 층).
합성할 때 그 꼬리표를 보고 색을 고르므로, 같은 CGA 색이라도 철골·벽돌·사다리·사람이 서로 다른 색으로 나온다.

* XOR 로 그리는 움직이는 그림은 목록으로 들고 있다가 따로 그린다 (화소마다 보임/안 보임 마스크).
* 모델과 실제 CGA 화면을 견주어 어긋난 자리는 CGA 를 따른다.
* 날아오는 못과 크레인 줄은 점 층으로 따로 둔다.
* 느린 기계(386/486)를 위해: 고정 그림 캐시, 바뀐 줄만 다시 그리기, 줄 예산.
  **움직이는 그림이 걸친 줄은 절대 미루지 않는다** — 미루면 인물이 두 장에 나뉘어 몸이 잘려 보인다.

## 더한 조작

| 키 | |
|---|---|
| `Ctrl+Q` | 언제든 도스로 끝내기 |
| `Alt+→` / `Alt+←` | 다음 / 앞 단계로 (게임 중에는 점수와 목숨을 그대로 두고 옮긴다) |
| `-1` … `-8` | 실행할 때 붙이면 그 배수로 빠르게 |

원본 조작은 [`release/README.TXT`](release/README.TXT) 에 적어 두었다.

## 만들기

```
build.bat            도스판 (djgpp + CWSDPMI)
sh build_host.sh     윈도/리눅스에서 돌려보는 판 (검사용)
```

## 맞는지 확인하기

* `tools/emu.py` (unicorn 으로 원본 `HHMACK.COM` 을 그대로 돌림) 과 `hosttest.exe` 를
  키를 보는 지점마다 레지스터와 메모리 CRC 까지 견준다 (`tools/regress.sh`).
* VGA 쪽은 [`shots/ref`](shots/ref) 의 기준 화면 14장과 바이트까지 같아야 한다
  (`a*` = `tools/_k7.txt`, `b*` = `tools/_k9.txt`).
* 디버그 판(`-DVGADEBUG`)은 유령 그림(GHOST), 모델 어긋남(INCONS),
  부분 갱신이 빠뜨린 자리(HHSTALE)를 찍어 준다.

저작권은 여전히 원저작자에게 있다.
